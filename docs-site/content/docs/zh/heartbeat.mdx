supabackup 可以对接 healthchecks.io 一类的外部死人开关：每次**成功且新鲜**的备份
后 ping 一次；生产路径失败时 ping `<url>/fail`。

## 配置

在数据库的“计划与心跳”抽屉中：

- **心跳 URL**：留空 = 继承服务器级 `SB_HEARTBEAT_URL`；`-` = 显式禁用（成功与失败
  ping 都不发）。
- **期望周期（小时）**：必填（URL 非空时）。超过 周期+宽限 未 ping，外部监控告警。
- **宽限（小时）**：对周期的额外容忍。

## 发送条件（成功 ping）

1. 存在有效 URL（库级或兜底）且未被 `-` 禁用；
2. 期望周期 > 0；
3. **本次成功运行**的导出起点（dumpStart）到现在 ≤ 周期 + 宽限——不是完成时刻，
   也不是轮询历史最新记录：一次超长运行的成功备份同样可能不 ping；
4. 若配置了远端目的地：该备份必须已远端提交（本地-only 部署例外）。

失败 ping 不受年龄门控限制（失败本身就是信号），但同样尊重 `-` 禁用。外部监控的
告警周期需要你在监控服务侧单独配置；supabackup 只负责 ping。

<Callout>
一个 URL 只能表达“这个监控点还活着”。多库共享一个兜底 URL 时，任一健康库都会
刷新它——需要逐库监控时，请为每个库配置独立 URL。
</Callout>
