## 任务状态

| 状态 | 含义 |
|---|---|
| `pending` | 已入队 |
| `running` | 正在执行 |
| `succeeded` | 导出+加密+（若有目的地）远端提交全部成功 |
| `failed` | 任一阶段真实失败；附错误类与排查建议 |
| `canceled` | 用户取消 |
| `interrupted` | 实例停机/崩溃中断；可被启动续传收敛 |

<Callout>
`succeeded` 不包含“已恢复验证”的含义。验证结果在任务的 verifyStatus
（`verified` / `failed` / `unsupported` / `not verified`）单独展示。
</Callout>

## 错误类与第一步排查

七类：`network`（连通/超时）、`auth`（凭据被拒）、`permission`（权限不足）、
`client_version`（pg_dump 比服务器旧）、`disk`（本地空间/配额）、
`storage_upload`（远端上传/回读失败，本地密文保留）、`verification`（导出完整性校验）。
失败行会展示该类对应的排查第一步。

## 下载形态

1. **恢复套件**（`restore-job<N>.sh`）：含哈希门禁与解密/恢复步骤的成功备份脚本。
2. **本地密文**（`backup-job<N>.dump.age`）：暂存区中的工件，同源下载。
3. **桶内对象**（presigned URL，15 分钟有效）：仅对已远端提交的备份提供。

三者都需要已登录会话；匿名请求一律 401。

## 并发与去重

同一库同时只允许一个排队/运行中的任务；重复触发返回 409（界面提示“已有任务在
排队或运行”）。
